## 1. Technical Hurdles & Failure Modes Encountered

1. **Solver Stalling on Stiff Simscape Differential-Algebraic Equations (DAEs):**
   - **Hurdle:** During initial testing with Simulink's default variable-step solver (`ode45`), the simulation hung for over 10 minutes on a 0.05-second time horizon. Simscape Electrical physical networks generate stiff coupled nonlinear DAEs that force explicit Runge-Kutta solvers into microscopic time steps ($< 10^{-12}\text{ s}$).
   - **Resolution:** Replaced the continuous explicit solver with an L-stable implicit discrete local solver (`Backward Euler`, `NE_BACKWARD_EULER_ADVANCER`) inside `Solver Configuration`, paired with Simulink's `FixedStepDiscrete` engine at $T_s = 50\,\mu\text{s}$ ($20\text{ kHz}$). Backward Euler provides infinite numerical damping as frequency approaches infinity, perfectly suppressing high-frequency stiffness from stator/rotor leakage inductances. Simulation elapsed time plummeted from $> 10\text{ minutes}$ (stalled) to $6.98\text{ seconds}$ for $0.1\text{ s}$ of dynamics.

2. **Simscape Electrical Library Search Path for Modern MATLAB Releases:**
   - **Hurdle:** In MATLAB R2026b, the legacy `powerlib` blockset is unified into Simscape Electrical. The Specialized Power Systems `Asynchronous Machine SI Units` block is encapsulated under `elec_conv_AsynchronousMachineSIUni.slx` located in `matlabroot/toolbox/physmod/elec/assistant/m/transform/`. Standalone execution of `setup_motor_params.m` failed with `Cannot find library called 'elec_conv_AsynchronousMachineSIUni'` because this directory was not on the default path.
   - **Resolution:** Added automated path detection in `setup_motor_params.m` and `build_simscape_model.m` to append `matlabroot/toolbox/physmod/elec/assistant/m/transform` dynamically if not already present.

3. **Recursive Invocation Safeguard:**
   - **Hurdle:** Initial drafts of `setup_motor_params.m` checked for the presence of `mit_simscape_model.slx` and attempted to invoke `build_simscape_model()`, while `build_simscape_model()` invoked `setup_motor_params()`, resulting in circular recursion.
   - **Resolution:** Decoupled parameter configuration from model construction. `setup_motor_params.m` sets up the base workspace and validates an existing model, while `build_simscape_model.m` is the sole builder.

## 3. Key Architectural Takeaways for Future Sessions

1. **Implicit Solvers for Simscape Electrical:** Never use explicit solvers (`ode45`, `ode23`) with Simscape electrical machines. Always configure an implicit solver (`ode23tb`, `ode15s`, or local `Backward Euler` with $T_s \le 50\,\mu\text{s}$) to avoid severe execution stalls.
2. **Library Path Portability:** When working headlessly with modern Simscape releases (R2024b+ through R2026b), dynamically ensure `toolbox/physmod/elec/assistant/m/transform` is added to the MATLAB path before loading conversion blocks.
3. **Programmatic Model Generation:** Programmatic assembly via `build_simscape_model.m` provides reproducible, version-controlled Simulink models without requiring graphical GUI sessions.
